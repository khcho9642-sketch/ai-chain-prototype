# 시나리오 분석

## 사용 흐름

사이트의 `#scenario`에서 한 가지 변화와 크기, 지속기간을 선택하면 9개 섹터와 주요 기업의 조건부 가치 변화를 계산한다. 사람이 입력값을 정하며, 강세·중립·약세 서사를 자동 선택하지 않는다. 기존 Today·시세·지도·커뮤니티 경로를 유지한다.

시나리오는 금리 변화(%p), AI CAPEX 변화(%), HBM 가격·공급 변화(각각 %), GPU·데이터센터 임대료 변화(각각 %), 모델매출 성장률 변화(기준 연간 성장률과 변경 성장률)다. CAPEX는 확대와 축소를 모두 지원한다. HBM 가격과 물량, GPU 요금과 데이터센터 공간·전력 임대료를 서로 동일한 충격으로 취급하지 않는다.

9개 섹터는 반도체 소부장 / 파운드리·패키징 / 메모리 / AI 칩 / AI 장비 / 전력·냉각 / 데이터센터 / 클라우드·GPU 컴퓨팅 / AI 모델이다. 이 챕터는 사용자가 확정한 9개 SEG를 사용하며, 기존 8개 고리 시세·지도 분류를 재사용하지 않는다.

애플, 마이크로소프트, 엔비디아, 아마존, 알파벳, 메타, 테슬라는 항상 표시한다. 주요 기업만 포함하며 여러 섹터에 속한 기업의 전사 가치는 회사 ID별로 한 번 계산한다. 섹터 소속은 실제 매출 비중을 뜻하지 않는다. 테슬라와 xAI는 합치지 않는다.

## 화면 구성과 첫 읽기

기존 방문 기록이 있어도 페이지를 새로 열면 **금리 +1%p·12개월**로 시작한다. 이 값은 첫 비교를 위한 예시 입력이다. 열린 화면에서 금리 0이나 다른 지속기간을 선택하면 해당 입력으로 계산한다. 다른 시나리오에서 저장한 입력과 기업별 가정은 그 시나리오를 선택할 때 다시 사용한다. 관측·환산주가는 페이지를 열 때 숨기고 사용자가 토글을 켜면 표시한다.

첫 결과표는 Big 7을 고정 순서로 보여준다. 그 아래 표에서 9개 섹터별 대표기업을 한 번씩 보여주고, 마지막에 두 집합과 중복되지 않는 나머지 기업을 표시한다. 현재 대표 ID는 `ASML / TSM / 000660.KS / NVDA / SMCI / VRT / EQIX / MSFT / META`다. 현재 41개 회사 중 대표기업과 Big 7의 중복은 NVDA·MSFT·META 3개이므로, `대표 9개 ∪ Big 7`을 제외한 기타 기업은 28개다. Big 7만 제외해 세면 34개다. 9개 대표기업 표의 열은 `섹터 / 대표기업 / 직접효과 / 밸류체인효과 / 총 EV 변화` 순서다.

Palantir(`PLTR`)는 기존 사이트의 종목 목록에는 있지만 현재 시나리오 `COMPANIES` 41개에는 없다. 따라서 이번 화면에서 Palantir를 대표기업이나 기타 기업으로 임의 삽입하지 않는다. 포함하려면 회사별 섹터·가정·노출도와 검증을 갖춘 데이터 변경이 먼저 필요하다.

기업 표의 `직접효과 / 밸류체인효과 / 총 EV 변화`는 `scenario-view-model.js`가 엔진 결과를 화면용으로 정리한 값이다. 직접·밸류체인 분해는 엔진의 경로 기여도에 비례 배분한 **Grade C 설명값**이다. 표시 반올림에서 생긴 미미한 잔차만 조정할 수 있으며, 큰 미배분 잔차를 직접효과에 흡수해 합계가 맞는 것처럼 보이지 않는다. 잔차가 허용 오차를 넘으면 분해 불일치와 잔차를 별도로 드러내고 검토가 필요한 값으로 표시한다. 실제 현금흐름의 감사 가능한 분해나 인과효과 추정치로 표시하지 않으며, 경로별 계수가 엔진 결과에 없으면 임의 계수를 만들지 않는다.

## 계산값과 실제 자료의 구분

상장사 38개의 기준매출은 로컬 재무 DB에서 선택한 각 회사의 최신 연간 연결 매출이다. 화면에 결산일, 보고 통화, 채택한 출처를 표시한다. 2026-11-05 스냅샷의 최신연도 입력은 네이버금융과 야후파이낸스에서 수집한 관측값이다. 출처 등급이 낮은 외부 집계값을 공시 직접 확인으로 승격하지 않는다. OpenAI·Anthropic·DeepSeek는 공개 연간 재무가 없어 기준매출 100의 섹터 예시를 사용한다. 섹터 자체의 지수와 기업별 지수는 각각의 기준가치 대비 변화율이다.

성장률은 통화·연결 범위·알려진 회계기준이 비교 가능한 연속 연도 매출에서 최근 최대 3년의 연평균 증가율을 구한다. 향후 1년차 성장 가정에는 −5%~30% 범위를 적용하고 원래 실측 성장률도 표시한다. 현금흐름 마진은 (영업현금흐름 − 유형자산취득액의 절댓값) ÷ 매출, 투자 비율은 유형자산취득액의 절댓값 ÷ 매출이다. 최근 실적의 음수 현금흐름도 보존한다. TSMC와 ASE는 기준매출에는 DB의 우선 출처를 유지하되 현금흐름률과 투자 비율에는 현금흐름표와 회계기준·통화·범위·기간이 일치하는 별도 매출을 사용한다. 비교 가능한 같은 기준의 매출 이력이 있으면 그 시계열에서 성장률을 구한다. 채택한 자료의 출처는 상세 패널에서 확인할 수 있다. 디지털 리얼티는 최신 투자액이 없어 실측 마진·투자 비율을 산출하지 않고 해당 예측 항목에 섹터 가정을 적용한다.

기본 전망은 1년차에 실적에서 구한 비율, 2년차에 이 값과 섹터 장기 가정의 중간값, 3~8년차에 장기 가정을 사용한다. 사용자가 수정한 항목은 입력값으로 계산한다. 할인율, 영구성장률, 충격 전달 비율과 시차는 가정이다. 영업현금흐름에서 투자액을 뺀 값에는 이자·세금·리스의 회계처리 차이가 남아 있다. 이 값으로 할인한 금액은 기업가치 민감도를 살펴보는 근삿값이며 완전한 무차입 현금흐름(FCFF) 평가와 구분한다. 기준가치가 0 이하인 경우 해당 기업의 변화율을 산출하지 않는다.

관측시가는 기존 공개 시세 스냅샷의 종목·통화·관측시각·출처와 함께 표시한다. 정상 상태이며 양수인 관측값만 환산에 사용한다. 관측시가에 가정 기반 지분가치 변화비율을 곱한 값은 **관측시가 기준 환산주가**이며, DCF 절대 내재주가·실제 미래 주가·보장된 수익률이 아니다. 현재 시세와 과거 관측시세를 혼동하지 않는다. 시세를 못 읽으면 계산 자체는 유지하되 가격은 미연결로 남긴다. 비상장 AI 모델 회사에 상장주가를 만들지 않는다.

기업별 가정을 변경할 수 있으며 변경된 가정과 적용 입력은 결과에 유지한다. 사용자가 지정하지 않은 실제 시장점유율·계약단가·재무 수치를 자동 생성하지 않는다.

## 현재 계산 범위

8년간 회사별 기준 현금흐름에 물량·판매단가·단위원가와 시나리오로 인한 추가 투자 지출을 반영한다. 기준 현금흐름에는 이미 기준 투자액이 반영되어 있다. 시나리오의 추가 투자액만 한 번 더 반영한다. 공급 관계와 전파 시차는 설명용 가정이며 가장 긴 입력 기간과 전파 시차가 끝난 뒤 잔존가치를 계산한다.

화면을 간결하게 바꾸더라도 엔진의 전체 기간 범위는 유지한다. 충격 지속기간은 6~36개월을 6개월 단위로 검증하며, 화면의 빠른 선택 버튼에 보이지 않는 유효 기간도 엔진 입력으로 처리한다. 기간을 바꾸면 충격이 적용되는 월수가 달라지므로 직접 영향도 달라질 수 있다.

## 전파와 가치평가 원칙

- 외부 입력에서 수요·가격·원가·설비투자·공급제약을 계산하고 현금흐름과 할인율로 연결한다. 다른 기업의 주가 변화율 자체를 공급업체 매출 충격으로 전파하지 않는다.
- 금리는 회사별 할인율 반영과 수요·자금조달 경로를 구분한다. 기준금리 1%p 변화를 모든 회사의 할인율 1%p로 동일 적용하지 않는다.
- CAPEX 변화는 공급업체 주문, 투자기업 자신의 즉시 현금지출과 12개월 뒤 서비스 매출로 연결되는 가정 경로를 함께 바꾼다. 투자 확대를 자동으로 기업가치 상승으로 고정하지 않는다.
- HBM 가격은 판매단가·원가 경로, 공급량은 물량 경로로 분리한다. 물량 효과는 가정한 전이계수로 계산하며, 실제 수요 한도·생산 병목·재고 완충을 검증한 결과는 아니다. 기존 가동설비와 신규 공급의 차이는 추가 보정이 필요하다.
- 임대료 변화는 공급자 판매단가와 구매자 원가의 별도 경로에 반영한다. 데이터센터 임대료가 클라우드 비용을 거쳐 모델기업으로 전달되며 같은 비용을 다시 직접 부과하지 않는다. 고정 계약·갱신·신규 계약별 실측 반영 비율은 아직 없고 평균 전이계수를 가정한다.
- 모델매출 성장률은 매출 변화율과 다르다. 전년 매출이 100일 때 기준 성장률 100%는 매출 200, 변경 성장률 50%는 150으로 기준 대비 매출은 25% 감소한다. 기본 전파는 가격·효율이 동일한 사용량 변화 가정이며 가격 인상만으로 매출이 증가한 경우와 구별한다.
- 현금흐름 대용치에서 차입금 이자를 다시 차감하지 않는다. 순부채는 동일 평가시점의 기업가치에서 지분가치로 넘어갈 때만 반영한다.
- 임시 충격을 영구성장률 하락으로 자동 영속화하지 않는다. 충격 기간 이후 정상화와 발주·설치 시차를 모델 가정에 명시한다.
- 입력 0이면 기준 지수 100과 변화율 0이 유지돼야 한다. 범위를 벗어나거나 유한하지 않은 입력은 오류로 표시한다.

## 현재 검증에서 드러난 한계

- 금리 시나리오는 현재 각 섹터에 금리 경로를 직접 적용한다. 따라서 화면 분해에서 금리의 연쇄 영향이 0으로 나오는 것은 현재 엔진 경로의 결과이며, 보기 좋은 값을 만들기 위해 연쇄 효과를 채우지 않는다.
- 같은 금리 충격이라도 지속기간을 늘리면 직접 충격이 반영되는 월수가 늘어 직접 영향이 변한다. `연쇄 0`과 `기간에 따른 총·직접 영향 변화`는 동시에 성립할 수 있다.
- Palantir 미수록, 금리 연쇄 0, 회사별 경로 계수 미노출은 검증 불일치나 결측으로 정직하게 남긴다. 화면 계층이나 설명 문구만으로 데이터·엔진 사실을 바꾸지 않는다.

## 재무자료 갱신

로컬 재무 DB를 갱신한 뒤 프로젝트 루트에서 `npm run export:scenario-financials`를 실행한다. 기본 DB 위치는 `.local/financials/financials.sqlite`이며 다른 위치는 `npm run export:scenario-financials -- --db <경로>`로 지정한다. 출력한 `assets/scenario-financial-baselines.js`의 결산연도·통화·출처와 차이를 확인하고 테스트·빌드를 거쳐 배포한다. 운영 화면은 배포된 스냅샷의 수집 기준일을 표시한다.

## 파일과 검증

- `assets/scenario-data.js`: 9개 SEG, 대표기업, 5개 시나리오 입력 정의와 명시적 가정.
- `assets/scenario-financial-baselines.js`: 비공개 DB에서 선별한 연간 수치와 출처. DB, 원본 응답, 키는 비공개로 관리한다.
- `assets/scenario-actuals.js`: 결산 실적에서 회사별 예측의 출발값을 결정한다.
- `assets/scenario-core.js`: 입력 검증, 전파·현금흐름·가치 계산.
- `assets/scenario-view-model.js`: 대표기업·Big 7·기타 기업 묶음과 Grade C 직접/연쇄 표시 분해.
- `assets/scenario.js`, `assets/scenario.css`: 선택·입력·결과·가정 편집 화면.
- `index.html`: 기존 사이트의 메뉴와 `#scenario` 경로.
- `tests/data/scenario*.test.mjs`: 모델 불변식과 사이트 연결 검증. `npm test`와 `npm run build`에 통합한다.

개인별 입력 저장은 브라우저 로컬 상태이며 공유 투자전략·게시글 발행이 아니다. 새로운 수집 API, 외부 AI 호출 또는 기존 커뮤니티 워커 활성화는 필요하지 않다.
