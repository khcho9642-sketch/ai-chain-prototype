# 국내 기업 DART 공식 공시

## 연결 범위와 출처

국내 상장기업 18개의 공식 회사별 RSS에서 공시 제목·접수번호·접수시각·DART 원문 링크를 수집한다. [금융감독원 DART RSS 안내](https://dart.fss.or.kr/introduction/content6.do)의 회사별 RSS는 최근 5영업일 공시를 제공한다. 인증키가 필요 없는 공개 RSS를 사용하며 DART 재무제표 API를 사용하지 않는다.

2026-10-27 KST에 공식 종목코드 검색 결과에서 6자리 종목코드와 회사명을 대조한 8자리 고유번호를 `assets/company-disclosure-sources.js`에 기록했다. 각 항목은 종목코드·고유번호·공시 회사명·확인시각·공식 검색 URL·RSS URL을 보존한다. 해외 종목, 목록 밖 국내 기업과 전체 시장의 공시를 자동 포괄하지 않는다. 기업 고리·시세 카탈로그를 늘릴 때는 공식 연결 정보를 별도 확인해야 한다.

`https://dart.fss.or.kr/api/companyRSS.xml?crpCd=고유번호`의 회사 채널 이름을 먼저 검증하고, 각 항목의 발행회사명이 등록 회사와 정확히 일치하는지 확인한다. 공백·유니코드 표기를 정규화하며 부분 문자열 검색으로 연결하지 않는다. 회사가 다른 발행회사를 위해 대신 제출해 피드에 나타나는 항목은 제외한다. `feedItemCount`와 `excludedItemCount`는 원래 피드 수와 이 제외 수를 기록한다.

## 보존 자료의 의미

RSS의 현재 제공 범위와 이 사이트가 누적 보존한 범위는 다르다. 수집을 시작한 뒤 확보한 자료를 접수번호별로 합치고, 회사별 **성공 수집 시** 최근 90일·최대 500건으로 정리한다. 기존 접수번호가 다시 오면 중복 행을 만들지 않는다. 정정공시는 접수번호가 다르므로 별도 문서로 보존한다.

공시 원문은 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=접수번호`로 연결한다. 접수번호 날짜와 RSS 발표시각의 한국 날짜를 대조하며, 문서는 최신 시각·접수번호 순으로 정렬한다. 과거 전체 공시 이력을 복원하지 않고, RSS 제공 기간보다 긴 수집 공백의 공시를 모두 확보한다고 보장하지 않는다. 빈 피드의 성공은 이번 범위에 새 항목이 없다는 뜻이며, 회사에 공시가 전혀 없었다는 뜻이 아니다.

회사별 수집 실패 시 기존 항목과 마지막 성공 시각을 그대로 유지한다. 따라서 오류가 계속되면 이전 보존 자료에 90일보다 오래된 항목이 남을 수 있다. 다음 성공 수집에서 보존 기간·건수 제한을 다시 적용한다.

공개 스냅샷은 회사·수집 상태와 위 공시 메타데이터만 허용한다. 작성자, RSS 설명의 공시 본문, 인증정보, 임의 필드는 저장하지 않는다. 공시의 재무 수치를 추출하거나 AI 통계·투자 판단을 자동 확정하지 않는다. 기존 `ai-disclosures.json`의 OpenAI·Anthropic 공식 발표문 변경 감시·통계 검토 후보와 별도 자료다.

## 실행과 요청 간격

Node.js 24에서 프로젝트 루트에서 실행한다.

```sh
npm run collect:company-disclosures
```

`scripts/data/collect-company-disclosures.mjs`가 `data/company-disclosures.json`을 검증해 읽고 갱신한다. 마지막 시도로부터 15분이 지나지 않았으면 기본 실행은 외부 요청 없이 기존 자료를 반환한다. 운영자가 의도적으로 재확인할 때만 `npm run collect:company-disclosures -- --force`를 사용한다. 자동 예약에서 강제 옵션을 사용하지 않는다.

회사 요청은 순차 실행하며 요청 사이 최소 750ms를 둔다. 각 요청은 기본 15초 제한시간, 2MB 응답 크기 제한을 사용한다. 403·429 제한 응답을 받으면 남은 회사 요청을 중단한다. DTD·외부 엔티티를 처리하지 않고, 허용한 공식 HTTPS 주소 외부로 리디렉션하지 않는다. 공개 오류에는 원문 응답이나 임의 네트워크 예외를 복사하지 않는다.

GitHub Actions의 기존 약 30분 간격 Pages workflow가 검증된 이전 배포 상태를 복원한 뒤 수집기를 실행한다. 예약 작업은 지연될 수 있다. 수집 단계의 실패는 다른 시세·산업통계 수집과 배포를 막지 않지만, 최종 빌드는 공시 JSON 검증을 반드시 통과해야 한다. 파일 저장은 임시 파일을 쓴 뒤 교체한다.

## 상태와 시각

| 범위 | 값 | 의미 |
| --- | --- | --- |
| 전체 | `idle` | 성공 여부를 확인하기 전의 초기 상태 |
| 전체 | `ok` | 이번 시도에서 등록된 모든 회사 수집 성공 |
| 전체 | `partial` | 일부 회사만 성공, 나머지는 실패 또는 요청 제한으로 중단 |
| 전체 | `error` | 이번 시도에서 성공한 회사 없음 |
| 회사 | `not-collected` | 해당 회사의 첫 수집 전 |
| 회사 | `ok` | 해당 회사의 마지막 실제 시도 성공 |
| 회사 | `error` | 해당 회사의 마지막 실제 시도 실패, 이전 성공 자료가 있으면 유지 |

`lastAttemptAt`은 실제 확인을 시도한 시각이고 `lastSuccessAt`은 마지막으로 성공한 시각이다. 공시 접수시각 `publishedAt`과 별개다. 일부 성공에서 전체 `lastSuccessAt`을 갱신하지 않는다. 요청 제한 뒤 아직 요청하지 않은 회사의 이전 상태·시각도 유지한다. 결과를 해석할 때 전체 상태와 회사별 마지막 성공 시각을 함께 확인한다. 배포 상태 복원은 검증을 통과한 자료만 허용하며 더 최신인 로컬 성공 자료를 오래된 원격 성공 자료로 덮어쓰지 않는다.

## 화면과 읽기 전용 API

시세·기업(#data)의 국내 기업 카드에 **공식 공시** 펼침을 표시한다. 보존한 자료 중 최근 5건의 제목·한국 시간 접수시각·원문 링크를 제공하고, 회사별 마지막 성공 확인·오류·지연 상태를 함께 보여준다. 상단에는 전체 성공 시각, 확인된 회사 수와 보존한 공시 수가 표시된다. **공시 자료 다시 읽기**는 배포된 스냅샷을 다시 확인하며 원천 수집을 직접 실행하지 않는다.

| 환경 | 읽는 자료 |
| --- | --- |
| 로컬 `/api/company-disclosures` | 로컬 빌드의 `data/company-disclosures.json` |
| Vercel `/api/company-disclosures` | Pages가 배포한 같은 이름의 JSON을 조회·검증하는 프록시 |
| GitHub Pages | 정적 `data/company-disclosures.json` |

스냅샷 API는 GET·HEAD만 지원하고 쓰기 요청은 405로 거절한다. Vercel에서 확인할 수 없거나 JSON이 유효하지 않으면 502를 반환한다. 화면은 API 실패 시 함께 배포된 정적 JSON을 검증해 대체 표시하고, 이를 안내한다. 브라우저가 DART로 자동 수집 요청을 보내지 않으며, 읽기 API가 수집기를 실행하지 않는다. 사용자가 DART 원문·RSS 링크를 누르면 해당 공식 사이트를 직접 연다.

인증키가 필요한 DART 재무제표 API, 공시 본문 해설, 재무 수치 자동 반영은 후속 범위다. 커뮤니티의 영속 서버·Oracle 계정·운영 배포 준비 상태는 이 RSS 기능 추가로 변경되지 않는다.

## 최초 검증 기록

2026-10-27 01:27 KST 수집본에서 국내 18개 기업 확인·공시 24건을 검증했다. 이는 해당 시점에 수집해 보존한 메타데이터 수이며 전체 과거 공시나 DART 재무제표 API 연결을 뜻하지 않는다. 현재 성공 여부와 시각은 `data/company-disclosures.json`에서 확인한다. 당시 회사 연결과 RSS 형식 근거는 `research/dart/`에 보존한다.
