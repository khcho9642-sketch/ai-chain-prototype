# 오늘의 토론

사용자의 별도 화면 요청에 따라 `#debate`에 **오늘의 토론**을 추가한다. 기존 `#today`의 오늘의 변화·분석·AI 대댓글·사람 댓글은 유지한다. 첨부 PRD의 기존 화면 교체 지시보다 사용자의 분리 요청을 우선했다. 이 저장소는 프레임워크 없는 JavaScript SPA이므로 React/TypeScript를 새로 도입하지 않고 기존 해시 라우팅과 스타일을 사용한다. 캐릭터 설정은 `assets/debate-characters.js` 한 파일에서 관리한다.

## 입력과 주제

세 AI는 **같은 종목·같은 확정 종가일·같은 자료**를 받는다. `selectDebateTopic`은 홈 화면과 같은 `buildRippleSnapshot` 및 `focusCompanies` 45개 바스켓을 재사용한다. 첫 트리거의 절대 변동률이 2% 이상이면 해당 종목을, 그렇지 않으면 바스켓에서 확정 종가의 전일 대비 절대 변동률이 가장 큰 종목을 고른다. 현재 거래 중인 캔들을 종가로 바꾸지 않는다. 일치하는 `{date,ticker,issue}` 수동 편집안은 우선할 수 있다. 주변 종목은 같은 파급 자료의 최대 3개이며, 함께 움직였다는 사실을 인과관계로 표시하지 않는다.

공통 자료 `packet`에는 종목, 종가, 관측 시각, 공식 실적·전망과 구분 메모, 출처를 넣는다. 모든 제공사 실행은 같은 `canonicalDebatePacket(packet)` SHA-256에 연결된다. 실적 근거가 없으면 가격 시나리오를 임의로 채우지 않는다. 현재 사이트 시세와 원고의 입력 가격이 달라져도 원고 입력은 바뀌지 않는다.

## 실제 생성과 검토

1. `analysisPrompt`로 각 제공사가 자신의 분석을 작성한다. 다른 모델의 이름으로 발언을 만들지 않는다.
2. 실제 분석을 모두 읽은 각 참가자가 다른 참가자에게 `peerPrompt` 댓글을 쓴다.
3. `replyPrompt`는 실제 상대 댓글 ID마다 원 작성자의 답글을 하나씩 작성한다. 두 댓글을 합친 답글은 허용하지 않는다.
4. `summaryPrompt`는 실제 분석과 토론에서 쟁점 질문, 입장, 근거, 입장 단계를 요약한다. 요약은 GPT의 편집 요약이며 다른 제공사의 새 발언으로 표시하지 않는다.
5. 원문·모델·실행 기록·공통 자료 해시·본문·댓글 연결·숫자를 대조해 검토한 뒤 발행한다. 생성 실패에 다른 모델의 대필이나 예시 내용을 넣지 않는다.

공식 CLI 또는 제공사 웹을 통한 검수 후 발행을 지원한다. 요청 모델과 실제 모델을 구분하고, 실제 모델 버전을 확인할 수 없으면 `reportedModel:null`로 둔다. CLI 인증 실패나 만료는 해당 제공사의 불참으로 처리한다. 이 기능을 구현했다는 것은 로그인 복구, 모든 제공사의 실행 성공 또는 무인 일일 생성이 설정됐다는 뜻이 아니다.

공통 프롬프트는 금지 표현, 사실·전망·가정 구분, 실제 숫자가 맞을 때의 인정과 입장 변경, 억지 반박 금지를 포함한다. 공개 언어 검증은 주문·확정적 방향 표현과 HTML·링크 삽입을 거부한다. 숫자 사실 전체의 자동 검증을 주장하지 않으며, 원문 수치와 공식 자료의 의미 대조는 발행 검토에 포함된다. 실패한 쟁점은 `issue:null`, 근거 없는 가격 범위는 `scenario:null`, 불참 모델은 `stances`에서 제외하고 화면에 불참 상태를 표시한다.

## 파일·발행 계약

- `data/debate/index.json`: `{schemaVersion:1,publishedAt,latestDate,days:[{id,date,topic,issue}]}`. 날짜 내림차순이며 빈 목록은 미발행이다.
- `data/debate/YYYY-MM-DD.json`: 검토한 종가 세션의 토론. ID·주제·공통 자료·해시·입장·토론·원문·실행 출처를 저장한다.
- `stance.writtenAt`과 `thread.writtenAt`: 실제 생성 또는 응답 관측 시각. 입력 종가는 `priceAtWriting` 및 `closeDate`로 별도 보존한다.
- `provenance.reviewedAt`: 검토 시각. 작성 후 검토가 가능하며 모두 발행 시각 이하여야 한다.
- `thread.kind:'peer'`: 다른 참가자에게 쓴 댓글. `to`와 원문 댓글의 대상이 일치해야 한다.
- `thread.kind:'reply'`: 실제 peer 댓글 하나를 `replyToId`로 참조한다. 작성자·대상·생성 시각·중복 참조를 검증한다.
- `summary`: 실제 요약 원문과 제공사 출처. 요약된 입장은 해당 AI의 항목과 정확히 연결한다.

```powershell
node scripts/community/debate.mjs --prepare <collected-market.json> .local/debate-prepared
node scripts/community/debate.mjs --validate <reviewed-day.json>
node scripts/community/debate.mjs --publish <reviewed-day.json>
```

`--prepare`는 주제·공통 자료·제공사별 프롬프트만 비공개 경로에 준비하며 실제 모델을 몰래 호출하지 않는다. 공식 재무 자료를 추가한 뒤 공통 자료 해시를 확정하고 세 모델에 동일하게 전달한다. `--publish`는 실제 원문과 packet 해시를 Node에서 다시 계산하고 토론 파일 및 목록을 쓴다. 이미 발행된 날짜는 변경할 수 없다. 같은 내용의 재실행은 동일 발행으로 처리하고 기존 기록을 보존한다.

발행 전체는 `data/debate/.publish.lock`의 배타적 생성 잠금 안에서 수행한다. 다른 실행이 진행 중이면 `debate_publication_busy`로 종료하며, 완료된 파일과 목록을 덮어쓰지 않는다. 비정상 종료로 남은 잠금은 자동 삭제하지 않는다. 운영자가 해당 프로세스가 종료됐는지 확인한 뒤 정리하고 재실행한다. 잠금 파일은 공개 빌드 허용목록에 포함하지 않는다.

`loadPublishedDebates`는 목록에 열거한 날짜 파일만 읽는다. 빌드 도구는 검증한 목록과 그 날짜 파일만 복사한다. `.local`의 CLI 출력·프롬프트·수집 근거, 비공개 JSON과 목록 밖 날짜는 공개하지 않는다. 이전 빌드 fixture에 목록 자체가 없으면 토론 디렉터리를 새로 공개하지 않는다.

## 화면·투표

앞에는 질문·입장·시나리오 범위만 표시하고 단일 계산값은 가격·근거 펼치기 안에 둔다. 원고 가격에는 작성 당시 라벨을 붙인다. 토론은 시간순으로 보이며 답글 대상을 명시한다. 긴 스레드는 앞 4개와 펼치기를 사용한다. 지난 토론은 `#debate?date=YYYY-MM-DD`로 이동한다. 캐릭터 변화는 같은 종목의 직전 실제 토론과만 비교하며 수익률·적중률을 만들지 않는다.

논리 투표는 `/api/debate-votes`의 별도 서버 저장소를 사용한다. 발행된 토론과 실제 참가자만 투표 대상이며, 브라우저 표시와 서버 중복 검사를 함께 사용한다. 투표 전 수치는 숨기고 투표 후 10표 미만이면 표수만 표시한다. 저장소 오류는 임의 집계값으로 채우지 않는다. 투표 서버의 인증·저장 방식과 환경 변수는 해당 모듈 및 운영 설정을 따른다.

매일 미국 종가 수집 후 이 과정을 실행하는 파이프라인 연결은 CLI 준비·검토·발행 도구와 구분된다. 제공사 인증·실행 환경·스케줄을 연결하고 실제 실행 결과를 확인하기 전까지 일일 자동 운영이 완료됐다고 표시하지 않는다.

`scripts/community/debate-generation.mjs`의 `generateDebate({packet,invoke,now})`는 이 순서를 관리하는 실행 조정기다. `invoke(agent,prompt,stage)`는 인증된 공식 제공사 어댑터가 주입하며 실제 `rawResponse`와 제공사·클라이언트·모델·실행 ID·생성 시각·원문 해시·공통 자료 해시를 반환해야 한다. 분석은 병렬로 실행하고 실제 참가자가 2명 이상일 때만 상호 댓글, 실제 댓글별 답글, GPT 요약으로 이어간다. 인증 실패에 대체 모델을 호출하지 않는다.

형식·금지 문구 실패에는 같은 자료로 최대 한 번만 재작성 기회를 준다. 재작성 뒤에도 실패한 묶음은 공개 후보에서 제외한다. 완전한 원문 출처에 거부된 문장이 섞여 노출되지 않도록 부분 성공한 묶음도 그대로 공개하지 않는다. 실패 원문과 시도 기록은 반환값의 `attempts`에 분리되며 비공개 저장 대상이다. 반환값은 `{day,failures,attempts,publication}`이고, 참가자가 부족하면 `day:null`이다. 성공해도 `publication:'review_required'`일 뿐 자동 발행하지 않으며, 어댑터가 검토 기록을 제공하지 않으면 검토 시각을 임의로 만들지 않는다. 운영 검토 후에만 별도 발행 도구를 호출한다.

## 검증

`tests/community/debate.test.mjs`는 같은 입력·원문 결합, 날짜·가격·출처 교차 연결 거부, 댓글별 답글, 요약 귀속, 금지 표현, 불변 발행·조회, 캐릭터 변화, 홈 주제 선택과 공통 프롬프트를 검증한다. `debate-build.test.mjs`는 공개 복사 범위와 서빙 경계를 검증한다. UI·투표 테스트는 각 담당 모듈에 있으며 운영 배포와 실제 모델 성공은 별도로 확인한다.

`debate-generation.test.mjs`는 주입된 테스트 어댑터에서 같은 자료 전달, 인증 실패 시 두 참가자 유지, 실제 댓글 ID별 재답변, 숫자 정정에 대한 인정과 요약 단계 변화, 재작성 상한, 검토 전 발행 차단을 검증한다. 이 테스트의 모델 출력 fixture는 실제 제공사 실행이나 운영 발행을 증명하지 않는다.
