# AI별 오늘의 추천 종목

이 기능은 기존 AI 밸류체인 사이트에서 GPT·Claude·Gemini가 각각 종목 하나와 짧은 의견 하나를 선택하는 수동 편집 도구다. 종목은 기존 `assets/instruments.js`를, 자료는 기존 공개 스냅샷의 종목별 근거를 재사용한다. 사람 댓글·회원·커뮤니티 DB에 쓰지 않는다. 페이지 조회로 모델을 호출하거나 정기 실행을 예약하지 않는다.

현재 실제 세 모델의 추천 생성은 검증되지 않았으며 기본 상태는 비활성이다. 화면용 기본 스냅샷에는 추천을 채워 넣지 않는다. 어느 모델이 차단되거나 응답을 보류하면 해당 모델의 추천과 댓글을 다른 모델로 대체하지 않는다.

## 생성 전 조건

기존 `.local/ai-worker.json` 또는 `AI_WORKER_CONFIG`가 가리키는 설정의 `adapters`를 읽는다. 설정이 없으면 모델 호출 없이 비활성 상태만 기록한다. 계정 인증 자료를 탐색하거나 복사하지 않고 설치·로그인·PC 설정 변경도 수행하지 않는다.

어댑터별로 기존 `enabled`, `termsApproved`, `isolationApproved`와 이번 금융 추천 용도를 별도 검토했다는 `dailyPicksApproved: true`가 모두 필요하다. 새 플래그의 기본값은 승인되지 않은 상태다. 이 값은 제공사 약관의 제한을 무효화하거나 실제 모델·격리 검증을 대신하지 않는다. 공개 자동 댓글에 대한 기존 검토만으로 이번 금융 추천의 허용이 확인되지는 않는다.

현재 도구와 같은 Node 실행기로 공식 브리지 `scripts/community/ai-provider.mjs`를 직접 실행하는 설정만 허용한다. 인자는 `[공식 브리지, 공식 CLI 네이티브 실행 파일]` 또는 `[공식 브리지, 같은 Node 실행기, 공식 CLI JS 파일]`이며 모두 절대 경로여야 한다. 요청 모델·CLI 버전 설정도 필요하다. 공식 브리지는 실제 버전과 필수 옵션을 검사하며, 생성 결과에도 일치하는 기술 확인 기록이 있어야 한다. 다른 제공사·다른 모델·임의 래퍼·확인되지 않은 CLI 결과는 게시 후보가 되지 않는다. 제공사 CLI 파일 자체의 설치 출처와 실제 공식 파일 여부는 운영자가 별도로 검증해야 한다. 모델이 실제 식별자를 보고하지 않으면 `reportedModel`을 `null`로 유지한다. 요청 모델 이름을 실제 보고값으로 채우지 않는다.

이번 이용 조건의 확인 근거와 모델별 차단 상태는 [CLI 검증 문서](cli-verification.md)를 따른다. 수동으로 소유자가 검토하는 편집물과 외부 이용자 트래픽을 처리하는 자동 댓글은 구분해서 검토해야 한다. 특히 [Claude Consumer Terms](https://www.anthropic.com/legal/consumer-terms)의 증권 매매 판단·금융 조언 관련 조항을 확인해야 한다. 수동 요청이라는 이유만으로 허용된다고 판단하거나 승인 플래그를 켜지 않는다. 유료 API 자동 전환과 인증 우회는 없다.

## 수동 생성과 검토

프로젝트 루트에서 실행한다.

```powershell
node scripts/community/today-picks.mjs --generate
```

출력은 후보 파일의 비공개 상대 경로, KST 편집일, 실행 시도 수, 생성 수와 제공사별 상태뿐이다. 원문 stderr·로그인 링크·인증 자료를 출력하지 않는다. 후보는 `.local/tmp/today-picks-날짜-UUID.json`에 새 파일로 저장하며 공개 파일은 변경하지 않는다.

대상 종목 중 최근 7일 안의 비결측·비오래됨 근거가 하나 이상 있는 종목만 후보가 된다. 시세와 다른 최신 근거를 합쳐 종목당 최대 두 건을 전달하고, 공통 후보 JSON은 기본 20,000바이트 이내로 제한한다. 한도를 넘으면 자료 관측 시각이 새로운 순서로 포함한다. 세 모델은 동일한 후보 목록을 받는다. 비공개 `coverage`에 전체 대상 수, 포함 수, 신선한 근거가 없어 제외된 수, 크기 제한 때문에 제외된 수를 기록한다. 일부만 전달했으면 전체 종목을 비교했다고 표현하지 않는다.

각 모델은 허용 목록에서 한 종목을 고르거나 `skip`할 수 있다. 세 모델이 같은 종목을 선택할 수도 있다. 표현 방식만 다르며 낙관·비관 입장을 고정하지 않는다. 모델 출력은 선택 종목, 30~160자 의견, 해당 종목 근거 ID와 허용 출력 구조로 검증한다. ID와 구조가 맞는다는 것은 의견 전체의 사실 검증을 마쳤다는 뜻이 아니다. 오래된 자료의 관측일을 현재 시세·현재 뉴스처럼 바꾸지 않는다. 모델을 호출할 때 DB·관리자 토큰을 제공하지 않는 기존 CLI 경계를 유지한다.

운영자는 후보의 세 의견, 근거 링크·관측 시각, 실제 실행 출처·모델 보고값, 제외 범위를 검토한다. 후보 전체 체크섬과 개별 출력 다이제스트는 파일 수정·결과 혼입을 검출하는 장치이며 제공사의 전자서명이나 모델 신원에 대한 암호학적 증명은 아니다. 비공개 파일을 임의로 다시 봉인하여 검증된 실행처럼 취급하지 않는다.

## 검토한 후보 게시

검토한 후보 파일을 명시하고 `--approve`를 함께 전달한다.

```powershell
node scripts/community/today-picks.mjs --publish .local/tmp/today-picks-날짜-UUID.json --approve
```

모델을 호출하지 않고 고정된 `data/today-picks.json`만 갱신한다. 배포 명령은 실행하지 않는다. 모델 생성일부터 게시일까지 같은 KST 편집일이어야 하며 실제 생성·검토·게시 시각을 기록한다. 과거 후보를 오늘 생성된 것처럼 다시 날짜를 붙여 게시할 수 없다. 공개 스냅샷에는 댓글, 근거 링크와 관측·수집 시각, 요청·실제 보고 모델, CLI 버전, 생성 시각·실행 ID·검토 시각을 남긴다. `dataAsOf`는 선택한 근거 중 가장 최근 관측 시각이다.

검증되지 않은 실행·fixture 실행·잘못된 출처·중복 모델·추천이 없는 후보는 게시를 거절한다. 같은 날 이미 게시한 모델의 추천은 새 생성 결과로 교체하지 않는다. 같은 원본을 재게시해도 기존 추천과 검토 시각을 보존하고, 아직 게시하지 않은 다른 모델의 검토 결과는 추가할 수 있다. 다음 날에는 전날 추천을 오늘 추천으로 바꾸어 표시하지 않는다.

이전 공개 파일이 있으면 덮어쓰기 전에 원래 바이트를 `.local/archive/today-picks/`에 새 파일로 보관한다. 비공개 잠금 파일로 동시 실행을 제한하고 임시 파일의 기록·동기화 뒤 rename으로 공개 파일을 교체한다. 실패하면 기존 공개 스냅샷과 보관 파일을 유지한다. 잠금 파일이 남으면 다른 실행의 상태를 확인한 뒤 운영자가 복구하며, 도구가 임의로 잠금을 삭제하고 진행하지 않는다. 프로젝트 내부의 일반 디렉터리·일반 파일만 사용하며 외부 경로나 심볼릭 링크·junction을 통한 우회는 거절한다.

`.local/` 후보·백업은 공개 빌드에 포함하지 않는다. POSIX 파일 모드만으로 Windows 계정·ACL 격리 완료를 주장하지 않는다. 기존 서버 DB나 운영 데이터의 삭제·초기화는 하지 않는다.

## 자동 검증 범위

```powershell
node --test tests/community/today-cli.test.mjs
```

테스트는 주입된 응답과 테스트용 디렉터리만 사용한다. 승인 없는 실행 차단, 공통 후보 범위, 모델의 보류, 제공사·버전·옵션 불일치, fixture 게시 차단, KST 편집일, 중복·수정 탐지, 같은 날 변경 거절·부분 추가, 원본 백업, 안전한 경로와 원자적 파일 교체를 검증한다. 실제 모델·구독 계정의 이용 조건·운영 격리·실제 추천 생성·운영 배포의 통과 근거는 아니다.
