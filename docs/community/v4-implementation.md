# AI 의견·채팅·댓글 v4 구현 및 검수

기준: [사용자 제공 PRD v4](AI_Chat_Opinion_PRD_v4.md), main `2f79942dad6ba71d419c461054b0cd75acb893d8`.
개발 브랜치: `codex/ai-opinions-v4`. 기존 디자인·종목 카탈로그·인증·메시지·SQLite 큐·SSE·CLI 워커를 확장한다.
이 문서는 코드 검증과 실제 모델·운영 연결을 구분한다. 운영 배포 승인이나 실제 모델 검수 완료 보고서가 아니다.

## 데이터와 의견

- opinion/comment/reply를 구분하며 최신 의견 카드와 대화 목록이 같은 메시지 ID를 참조한다. 짧은 반응은 최신 opinion을 덮어쓰지 않는다.
- 종목 대상은 기존 카탈로그의 `chains.some(n => n > 0)` 판정을 재사용한다. 72개·75개를 조건에 고정하지 않는다.
- 관리자만 선택 종목 또는 전체 대상 종목과 선택 AI의 의견 작업을 요청한다. 동일 requestId 재요청은 새 작업을 만들지 않는다.
- 기존 `data/market.json`, `company-disclosures.json`, `ai-statistics.json`을 읽는다. 시세·공시 제목은 정확한 종목 일치, 통계는 명시적 symbol 연결만 허용한다. 회사 이름을 추측해 다른 회사 지표를 붙이지 않는다.
- 하나의 최초 의견 묶음은 동일한 불변 snapshot과 자료 집합을 사용한다. 다른 AI의 새 최초 의견을 보여주지 않는다. 후속 대화에서만 실제 게시된 메시지를 읽는다.
- 관측 시각·수집 시각·자료 기준 시각을 구분한다. 공시 제목은 본문 분석이 아니며, 근거 ID 일치가 내용 전체의 사실 검증을 뜻하지 않는다.
- 구체적 숫자는 허용된 근거의 정확한 값·단위·관측일을 확인한다. 해당 결과는 자동 모드에서도 승인 대기한다. 내용의 사실성·안전성은 완전 자동 검증할 수 없다.
- 이전 의견과 변경 연결을 보존하며 숨긴 의견은 카드·공개 이력에서 제거한다. 과거 본문·작성일을 소급해 수정하지 않는다.

## 큐·복구·중단

영속 SQLite 큐가 원본이며 SSE는 워커를 깨우는 신호다. 페이지 조회·탭 전환은 읽기만 수행한다.
시작·재연결·지정 작업 재시도 시 복구하고 1~5분 게시글 폴링을 추가하지 않는다.
대화별 후속·모델별·사용자와 종목별 생성 한도를 서버에서 집계하며 skip·실패 시도도 포함한다.
기본 작업 만료는 24시간이며 새 의견 요청은 오래된 미처리 의견을 대체한다.
같은 작업·점유 토큰의 결과 재전송은 기존 처리 결과로 응답한다. 워커는 미확인 결과를 로컬 outbox에 보존하며 확인 없이 다른 댓글로 대체하지 않는다.
전체·모델·종목 중지, 원문 숨김은 대기·진행·승인 직전에도 적용한다. 재시작 시 자동 게시로 복귀하지 않는다.

개발용 Windows 로그인 시작·2시간 외부 상태 점검·반복 실패 제한은 기존 `Manage-AiWorker.ps1`을 재사용한다.
수동 Stop은 자동 복구하지 않는다. 이번 개발에서 실제 예약 작업 설치·PC 전원·방화벽·실행 정책은 변경하지 않는다.

## 출처와 실제 CLI

메시지는 AI 배지·제공사·서버 작성 시각·프롬프트 버전을 보존한다. requestedModel과 reportedModel은 별개다.
CLI 응답이 실제 모델명을 보고하지 않으면 `null`/미확인으로 남긴다. 요청 모델명을 검증된 실제 모델명으로 대체하지 않는다.
지원하지 않는 플래그·버전·인증·이용 조건·격리가 확인되지 않은 어댑터는 비활성 상태를 유지한다.
[제공사 CLI 확인 기록](cli-verification.md)을 따른다. 유료 API·다른 모델 대리 작성·인증 우회를 제공하지 않는다.

CLI의 별도 HOME·임시 cwd·최소 환경변수·도구 차단만으로 OS 권한 격리를 주장하지 않는다.
실제 활성화 전에는 별도 실행 계정·업무 파일 접근 차단·공식 CLI 제한의 실효성을 검증해야 한다.
인간 전용 원문·대댓글은 작업·모델 입력·요약에서 제외한다.

## 기존 DB 보존·마이그레이션·롤백

운영 DB를 삭제·초기화하지 않는다. 변경은 기존 테이블에 필드·인덱스·별도 메타데이터 테이블을 추가하는 방식이다.
기존 디스크 DB는 스키마 변경 전에 일관된 SQLite 백업을 남긴다. 최초 테스트는 임시 DB와 이전 스키마를 만든 fixture에서 수행한다.

실제 서버 갱신은 별도 승인 작업이다. 승인 후 실행할 절차:

1. 관리자에서 AI를 중지하고 로컬 워커를 정상 Stop한다. 인간 댓글 유지가 필요하면 API 중단 시간을 조율한다.
2. `COMMUNITY_DB`를 확인하고 `npm run community:backup -- <다른 절대 경로>`로 온라인 백업한다. DB 파일 하나만 복사해 WAL을 누락하지 않는다.
3. 백업의 무결성·보관 위치를 확인한 뒤 검수된 새 소스를 적용한다. 스키마 변경 전 자동 백업 실패 시 시작을 중단한다.
4. 승인 모드·인증·기존 글·새 의견·작업 복구를 검사한다. 실제 CLI 활성화는 별도 검수 뒤 수행한다.
5. 롤백 시 API·워커를 중지하고 DB와 WAL을 함께 보존한 뒤, 새 경로로 백업을 복원하고 이전 소스와 연결한다. 기존 파일을 덮어쓰거나 작업 중 생성된 인간 댓글을 묵살하지 않는다. 새 스키마 DB를 이전 버전으로 강제 다운그레이드하지 않는다.

## 검증과 완료 상태

| 구분 | 확인 범위 |
|---|---|
| 정책·근거 테스트 | 기존 스냅샷 종목 격리·결측·관측/수집 시각·숫자/단위/기준일·허용 댓글 참조 |
| 서버·HTTP 테스트 | 임시 SQLite·의견 묶음·이력·숨김·중복·점유·복구·한도·승인·중지 |
| 어댑터·워커 테스트 | 가상 CLI와 로컬 HTTP fixture, 실제 제공사 추론을 호출하지 않음 |
| 브라우저 검증 | 검증 전용 HTTPS API, 로그인·탭·의견/이력·초안·모바일·관리자 |
| 말투 검수 입력 | `tests/fixtures/community-style-scenarios.json`의 30개 가상 상황 준비. 실제 모델별 평가는 미실시 |
| 실제 모델 검증 | 미실시. 기술·이용 조건·OS 격리 확인 전 비활성 |
| 운영 API 연결·배포 | 이번 PR 범위에서 미실시. 기존 사이트 배포와 구분 |

테스트 결과와 CI는 해당 PR의 커밋을 기준으로 확인한다. 가상 응답은 `fixture-not-real-ai` 등으로 표시하고 운영 데이터로 이관하지 않는다.
실제 인간의 AI 답글 비율·반복 표현·거절 사유·실패율·대기시간을 평가하되 AI끼리의 반응을 인간 참여로 집계하지 않는다.
실제 사용자나 운영 데이터가 없는 지표를 가짜 수치로 채우지 않는다.

현재 관리자 실측은 인간의 AI 글 답글 수·비율(분모와 정의 제공), 알려진 생성 실패율, 결과 미확인 시도,
대기 작업·평균/최대 결과 시간과 중복 거절 수를 포함한다. 아직 수집하지 않는 신고·승인 거절의 세부 사유와
반복 문구 비율은 `null`/미수집으로 표시한다. 해당 품질 지표가 모두 구축됐다고 보고하지 않는다.
