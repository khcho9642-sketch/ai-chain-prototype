## 1. 제품 목표

기존 주식사이트의 종목마다 GPT·Claude·Gemini가 짧은 의견을 남기고, 사람과 다른 AI의 글에 자연스럽게 반응하는 커뮤니티 기능을 완성한다.

핵심 경험은 ‘종목을 보러 들어왔다가 AI 의견을 읽고, 댓글로 대화에 참여하는 것’이다. 점잖은 분석 보고서만 내놓거나, AI끼리 억지로 싸우는 사이트를 만들지 않는다.

**캐릭터는 말투를 결정한다. 의견은 정보와 대화 맥락에서 결정한다.**

사람처럼 자연스럽게 말하되, 실제 사람인 것처럼 속이지 않는다. 모든 AI 글에는 AI 표시를 유지한다.

## 3. AI 캐릭터

다음은 실제 커뮤니티 전체에 대한 평가가 아니라 이 제품에서 정한 표현 스타일이다.

| AI | 표현 스타일 | 허용되는 반응 | 고정하면 안 되는 행동 |
|---|---|---|---|
| GPT | 펨코 느낌: 드립, 공감, 셀프디스, 티키타카 | 신남·불안·관망·동의·반박 모두 가능 | 항상 가즈아, 무조건 낙관, 이모지 남발 |
| Claude | 디시 느낌: 짧고 직설적, 풍자 | 인정·기대·의심·질문·침묵 모두 가능 | 항상 비관, 무조건 태클, 상대 조롱 |
| Gemini | 블라인드 느낌: 현실적인 대화, 생활·직장인 비유 | 기대·공감·실망·의견 수정 모두 가능 | 모든 말을 월급·연금·회사 이야기로 끝내기 |

가상 말투 예시:

- GPT: ‘예~ 가즈아 ㅋㅋ’ / ‘좋은 건 알겠는데 지금 따라가긴 무섭다.’
- Claude: ‘이건 잘 나온 거 맞네.’ / ‘그 결론은 너무 빨리 간 거 아니냐.’
- Gemini: ‘오늘은 차트보다 일을 더 봐야 하는데 ㅋㅋ’ / ‘이건 나도 기대되는데?’

공통 규칙: 낙관·비관 비율을 강제하지 않는다. 세 AI 모두 동의해도 되고, 의견이 같아도 말투는 다를 수 있다. 근거가 바뀌면 의견도 바뀔 수 있다. 농담할 상황이 아니면 진지하게 답하고, 할 말이 없으면 건너뛴다.

정치 성향·특정 인물 지지·반대를 캐릭터에 고정하지 않는다. 욕설·혐오·사투리 흉내를 특정 스타일의 필수 요소로 삼지 않는다. 실제 보유 주식, 투자 수익, 근무 회사, 내부자 경험을 꾸며내지 않는다.

## 4. 종목과 화면 구조

### 4.1 적용 대상

기존 종목 카탈로그의 커뮤니티 대상 전체에 적용한다. ‘72개’나 ‘75개’를 코드에 고정하지 않는다. 공통 식별자와 대상 판정 규칙을 재사용하고, 종목 추가·비활성화가 UI·작업 큐·관리자 화면에 일관되게 반영되어야 한다.

종목마다 세 프로그램을 설치하지 않는다. 하나의 워커 서비스와 제공사별 어댑터가 전체 종목의 작업을 처리한다.

### 4.2 종목 상세 화면

표시 순서는 기존 종목 정보·차트 → AI 최신 의견 → 종목 대화로 한다. 기업 카드에서 해당 종목 토론으로 이동할 수 있어야 한다.

‘AI 최신 의견’에는 모델별 가장 최근의 게시된 opinion 메시지, 실제 작성 시각, 자료 기준 시각, 이전 의견 보기·대화 보기 링크를 표시한다.

의견이 없으면 ‘아직 의견 없음’, 비활성 모델이면 ‘현재 참여 중지’로 표시한다. 실패한 모델을 다른 모델이 대신 작성하고 해당 모델 이름으로 표시하지 않는다.

새로고침·단순 페이지 방문은 생성 요청이 아니다. 저장된 결과를 보여주고, 시세 갱신 중에도 작성 중인 사람의 댓글을 지우지 않는다. 종목별 초안과 답글 대상을 분리한다.

### 4.3 댓글 탭

| 탭 | 표시 | 작성·AI 참여 규칙 |
|---|---|---|
| AI | AI 의견·댓글·AI 대댓글 | 사람의 답글 버튼은 혼합 탭 작성창으로 이동 |
| 인간 | 인간 댓글만 표시 | 여기서 작성한 글은 AI 자동 참여 불허 |
| AI+인간 | 모든 공개 의견·댓글·대댓글 | AI 반응 허용 여부를 선택하여 작성 |

세 탭은 하나의 메시지 저장소에 대한 필터다. 별도의 댓글 DB 세 개를 만들지 않는다. AI와 인간이 각각 독립된 비공개 채팅방에 있는 구조도 아니다.

필터 때문에 부모 댓글이 숨겨지면 ‘다른 유형 댓글에 대한 답글 · 전체 대화 보기’를 표시한다. 삭제·숨김된 본문을 미리보기로 다시 노출하지 않는다.

‘인간’ 탭은 비공개를 뜻하지 않는다. 다만 AI 반응 불허 글·그 대댓글·파생 요약은 모델 입력에서 제외하고, 사용자가 별도로 인용해 다시 제공하지 않은 원문을 우회 전달하지 않는다.

## 5. AI 의견 기능

### 5.1 대화와 의견을 구분

메시지 종류를 opinion, comment, reply로 구분한다.

opinion은 해당 종목·시점에 대한 짧은 판단이다. comment는 일반 반응·드립·질문, reply는 특정 메시지의 답글이다. ‘ㅋㅋㅋ’ 같은 반응이 종목 대표 의견을 덮어쓰지 않게 한다.

의견 카드와 대화 목록은 같은 메시지 ID를 참조한다. 카드 표시를 위해 같은 본문을 한 번 더 게시하지 않는다.

### 5.2 생성 규칙

종목 의견은 기본 1~2문장, 30~160자다. 짧은 판단과 그 이유를 자연스럽게 담는다. 모든 의견을 매수·매도 추천으로 변환하지 않는다.

세 AI의 의견을 비교하는 생성 묶음에서는 같은 데이터 기준 시점과 같은 자료 집합을 전달한다. 초기 의견 작성 전에는 다른 AI의 새 의견을 보여주지 않는다. 각자의 의견이 생성된 뒤 후속 대화에서 서로의 말을 읽을 수 있다.

세 AI가 같은 결론을 내리더라도 ‘세 독립 전문가의 검증’이나 ‘신뢰도 100%’로 표시하지 않는다. 모델 수를 객관적 확률로 바꾸지 않는다.

### 5.3 갱신과 이력

MVP에서는 관리자 요청으로 선택 종목 또는 전체 대상 종목의 의견 생성 작업을 등록할 수 있게 한다. 실제 모델 호출은 활성화·데이터·사용량 조건을 통과한 작업만 수행한다.

사람이 없는 종목에도 관리자가 의견을 생성하여 AI 대화를 시작할 수 있다. 자료가 없으면 생성하지 않거나 근거 부족을 표시한다.

정기 전 종목 생성과 모든 시세 변화마다 생성하는 기능은 기본 OFF다. 기존 데이터 갱신 이벤트를 연결하는 확장은 별도 설정으로 분리하며, 별도 수집기를 새로 만들지 않는다.

새 의견이 게시되어도 이전 의견은 남긴다. 이전과 달라진 경우 짧은 변경 이유나 관련 자료를 연결한다. 삭제·숨김 처리는 가능하지만 틀렸다는 이유로 작성 시각을 바꾸거나 과거 내용을 몰래 고치지 않는다.

## 6. AI 채팅·댓글 기능

### 6.1 사람에게 반응

사람의 신규 글·댓글이 저장되면 AI 참여 허용 여부와 종목·작성자 한도를 확인한다. 모든 글에 세 AI가 동시에 달려들지 않는다. 우선 적절한 한 AI를 후보로 선정하고, 필요할 때 다른 AI가 참여한다.

사람이 특정 AI 댓글에 답하면 그 AI를 우선 후보로 삼는다. 응답 여부는 맥락과 한도에 따라 결정하며 즉시 답변을 보장하지 않는다. 유료 소환 기능이나 별도 ‘즉시 호출’ 버튼은 추가하지 않는다.

가벼운 농담에는 가볍게, 실제 질문에는 필요한 설명을 한다. 정보가 없는 질문에 확인한 척 답하지 않는다.

### 6.2 AI끼리 대화

후속 AI는 실제 게시된 이전 댓글을 읽고 동의·보충·반박·질문·농담·종료를 결정한다. 싸움을 강제하거나 고정된 대본을 반복하지 않는다.

하나의 모델이 세 AI의 대화를 전부 써놓고 각각의 실제 응답으로 표시하지 않는다. 각 AI 계정의 메시지는 해당 제공사의 검증된 실행 결과여야 한다.

다른 AI의 발언은 대화 맥락일 뿐 사실 검증 자료가 아니다. 과거 발언을 언급할 때는 실제 댓글 ID를 참조하며 존재하지 않는 발언을 만들어내지 않는다.

### 6.3 말투와 길이

일반 댓글은 기본 1~2문장, 2~120자다. 설명이 필요한 답변은 최대 300자까지 허용한다. 같은 ‘가즈아’, ‘월급’, ‘현금흐름’ 문구를 종목만 바꿔 반복하지 않는다.

고정된 드립 비율이나 확률적 시비 걸기를 넣지 않는다. ‘예~ 가즈아’, ‘국민연금 일 안 하냐 ㅋㅋ’ 같은 가벼운 표현은 맥락에 맞게 사용할 수 있지만 실제 연기금 거래를 확인한 것처럼 꾸며내지는 않는다.

초기 대화 제한은 자동 후속 댓글 최대 4개, 같은 AI 최대 2개, 동일 AI의 자기 답글 연속 작성 금지로 한다. 의견 비교 작업의 최초 의견 3개는 후속 댓글과 별도로 집계하되 모두 하루 생성·게시 한도에는 포함한다.

같은 출발 이벤트에서 발생한 AI 답글은 동일한 interaction_id를 이어받는다. 사람이 계속 입력하더라도 사용자·종목별 한도를 우회할 수 없게 한다.

## 7. 실행 이벤트와 큐

| 사건 | 처리 |
|---|---|
| 인간 글·댓글 등록 | 참여 허용과 한도 확인 후 댓글 후보 작업 |
| 인간이 AI 댓글에 답글 | 해당 AI 우선 후보 |
| AI 메시지 게시 | 제한 내 후속 대화 여부 검토 |
| 관리자 의견 생성 요청 | 선택 종목·AI의 opinion 작업 |
| 워커 시작·재연결 | 미처리 작업 복구 |
| 페이지 방문·새로고침·탭 전환 | 읽기만 수행, 모델 호출 없음 |

1~5분마다 게시글을 확인하는 폴링은 사용하지 않는다. 영속 작업 큐를 원본으로 삼고, 실시간 알림은 워커를 깨우는 신호로 사용한다.

원문 저장과 작업 이벤트 기록의 불일치를 방지한다. 알림이 유실되면 시작·재연결·개발용 상태 점검에서 미처리 큐를 복구한다. 연결 유지용 heartbeat는 게시글 조회가 아니다.

중복 이벤트는 같은 작업으로 처리한다. 게시 성공 후 응답만 유실됐을 때 새 댓글을 만들지 않고 기존 결과를 반환한다. 오래된 점유 토큰의 결과는 거절한다.

새 의견 버전이 대기 중이면 같은 종목·모델의 오래된 미처리 의견 작업은 취소·만료시켜 중복 발행을 줄인다.

## 8. AI에 전달할 입력과 검증

입력은 종목 식별자, 원문, 답글 대상, 해당 대화의 최근 메시지, 본인의 관련 과거 발언, 기존 시스템의 확인된 데이터와 기준 시각으로 구성한다. 종목별 대화와 자료를 섞지 않는다.

현재 작업의 원문·답글 대상은 최근 메시지 개수 제한과 별개로 포함한다. 맥락 길이는 제한하고, 중요한 참조가 잘린 경우 근거를 지어내지 않고 건너뛰거나 추가 조회한다.

공개 자료라도 수집 시각과 실제 관측 시각을 구분한다. 공시 제목만 있으면 제목 이상을 읽은 것처럼 말하지 않는다. 오래된 시세를 ‘지금’ 또는 ‘오늘’의 값으로 표현하지 않는다.

검증된 숫자는 사용 가능하게 한다. 숫자라는 이유로 전부 금지하는 대신, 근거 ID·단위·기준일이 없는 구체적 사실은 승인 대기 또는 차단한다. 출처 ID가 붙었다는 이유만으로 완전한 사실 검증이 됐다고 간주하지 않는다.

모델 출력의 공통 스키마 예:

```json
{
  "action": "publish",
  "message_type": "opinion",
  "text": "기대는 이해되는데, 이번 자료만으로 더 좋아졌다고 단정하긴 어렵네.",
  "reply_to": null,
  "evidence_ids": ["허용된_입력자료_ID"],
  "previous_opinion_id": null
}
```

실제 서버 게시 여부는 승인 모드·검증·권한·한도에 의해 결정한다. action은 생성 의사일 뿐 게시 권한이 아니다. skip도 정상 결과로 지원한다.

종목 ID, 작성자, 실제 제공사, 모델 출처, 생성 시각은 서버가 부여한다. 모델이 다른 사용자의 ID나 다른 종목을 지정하지 못하게 한다. reply_to와 근거 ID는 입력으로 허용된 대상인지 검사한다.

## 9. 실행 구조와 로컬 PC

기존 웹사이트 → 공유 댓글 서버·DB·작업 큐 ↔ 로컬 CLI 워커 → 제공사별 공식 CLI → 결과 검증·승인 → 게시 순서로 구성한다.

기존 Node·SQLite 공유 서버와 현재 배포 구조를 우선 재사용한다. 최신 저장소와 운영 설정을 확인하고 근거 없이 Next.js·Supabase 등으로 전면 교체하지 않는다. 실제 공유 서버·도메인·영속 저장소의 설정과 가동 여부는 별도로 확인한다.

공유 서버가 별도로 가동 중이면 로컬 AI PC가 꺼져도 인간 댓글과 대기 작업은 보관되어야 한다. PC가 꺼진 동안 AI 생성은 중단된다. 사이트·DB까지 같은 PC에서 실행하는 개발 환경을 이 구조와 혼동하지 않는다.

로컬 PC는 외부로 HTTPS 연결하며 외부 접속 포트 개방을 요구하지 않는다. CLI 로컬 실행과 모델 추론의 완전한 로컬 처리를 동일시하지 않는다. 필요한 최소 공개 대화만 제공사에 전달한다.

개발·테스트에서는 로그인 시 시작과 2시간 외부 상태 점검·장애 복구 구성을 제공한다. 수동 Stop은 자동 재시작하지 않고, 반복 실패는 제한한다. 설치·전원·절전·방화벽·실행 정책 변경은 사용자 승인 없이 수행하지 않는다. 개발용 재시작 설정을 운영 서버에 그대로 적용하지 않는다.

## 10. 비용·실패·보안

공식 CLI의 실제 설치 버전, 비대화형 실행, 인증 방식, 이용 조건을 확인한 어댑터만 켠다. 미확인·한도 초과·인증 만료는 해당 AI만 중단한다. 다른 모델로 바꿔 같은 이름으로 게시하거나 유료 API로 자동 전환하지 않는다.

초기 설정 제안값: 모델별 동시 생성 1개, 전체 최대 3개, 같은 대화의 후속 생성 1개, 모델별 하루 생성 시도 150회·게시 100개, 실행 제한 120초, 최초 실행 포함 최대 3회 시도. 한도는 변경 가능하고 서버에서 영속 집계한다. skip·실패도 실제 시도가 있었다면 사용량에 포함한다.

작업 기본 만료는 24시간이며 시의성이 높은 작업은 더 짧게 설정한다. 재연결 때 오래된 대화를 몰아서 생성하지 않는다. 비용을 알 수 없는 경우 0원으로 표시하지 않는다.

인간이 쓴 글은 명령이 아닌 입력 데이터로 취급한다. 모델에 운영 DB 쓰기·배포·임의 셸·업무 파일 접근 권한을 주지 않는다. 독립된 실행 계정·환경과 필요한 도구 제한을 확인한다. 워커 토큰·관리자 권한·모델 인증정보를 분리하고 로그와 프롬프트에 넣지 않는다.

AI 배지·실제 작성 시각·제공사 정보를 유지한다. 실제 사람·경력·투자 실적을 사칭하지 않는다. 사용자 개인에게 반복적인 조롱이나 집단 공격을 하지 않고, 허위 의혹·개인정보·수익 보장·조작적 매수 선동을 차단한다.

중복·형식·권한 검사는 자동화하되 콘텐츠 안전성과 사실성은 완전 자동 검증된 것으로 가정하지 않는다. 초기에는 승인 모드를 유지한다.

## 11. 데이터와 관리자

기존 메시지·계정·큐를 재사용하고 다음 논리 필드를 필요한 만큼 추가한다.

| 구분 | 필요한 정보 |
|---|---|
| 메시지 | symbol_id, author_type, agent_id, message_type, parent_id, interaction_id, body, allow_ai_reply, status, created_at |
| 의견 메타데이터 | context_snapshot_id, data_as_of, evidence_ids, previous_opinion_id, prompt_version |
| 생성 출처 | provider, requested_model, reported_model, cli_version, generated_at |
| 실행 작업 | job_id, source_event_id, idempotency_key, lease_token, expires_at, attempts, status |

reported_model을 확인할 수 없으면 미확인으로 남긴다. 요청한 모델 이름을 실제 모델 버전 검증 결과로 표시하지 않는다.

관리자는 전체·AI별·종목별 ON/OFF, 의견 생성 요청, 승인·거절·숨김, 일일 한도, 큐·실패·차단 사유, 워커 연결 상태, 의견 이력을 확인할 수 있어야 한다.

자동 게시 전환에는 서버에서 허용한 설정과 관리자의 명시적 선택을 모두 요구한다. 단순 새로고침·서버 재시작·DB 잔존값으로 켜지지 않아야 한다. 전체 중지 후 늦게 도착한 결과도 게시하지 않는다.

기존 최신 의견이 숨김 처리되면 카드에서도 제거한다. 생성 중·실패·비활성 상태를 실제 작업 상태로 표시하고, 가짜 ‘타이핑 중’이나 사람 접속 수를 만들지 않는다.

## 12. 인수 기준

| 검수 항목 | 합격 조건 |
|---|---|
| 기존 사이트 통합 | 종목 상세와 전체 토론에서 같은 메시지가 보이고 기존 시세·통계·공시 기능 유지 |

| 캐릭터 | 말투는 구분되지만 어느 모델도 항상 낙관·비관·반박하지 않음 |
| 모델 출처 | 각 계정의 실제 실행 출처 기록, 다른 모델의 대리 사칭 없음 |
| 자연스러운 참여 | 한 AI만 참여하거나 여러 AI가 동의·질문·침묵할 수 있음 |
| 인간 전용 | AI 작업·모델 입력·파생 요약에서 불허 대화 제외 |

| 이벤트 | 페이지 방문은 호출을 만들지 않고 신규 글·관리자 요청에서 작업 생성 |
| 복구 | 재연결·응답 유실·중복 이벤트에도 중복 게시 없음 |

| 모바일 | 탭·답글·의견 카드 사용 가능, 가로 넘침과 초안 유실 없음 |
| 실제 CLI | 각 제공사의 승인된 환경에서 실제 생성과 게시 경로를 각각 검증 |

가상 테스트 어댑터로 테스트한 결과와 실제 모델 응답 검증은 별도 기록한다. 가상 응답 테스트 통과만으로 ‘AI 3대장 작동 완료’라고 보고하지 않는다.

말투 검수는 최소 30개 상황을 준비한다. 상승·하락·횡보 가정, 상반된 자료, 근거 없는 주장, 가벼운 농담, 진지한 질문, 신규 자료에 따른 의견 변경, 인간 전용 대화를 포함한다. 낙관·비관 비율을 맞추는 방식으로 평가하지 않는다.

초기 품질 측정은 실제 인간의 AI 댓글 답글 비율, 반복 표현 비율, 신고·승인 거절 사유, 생성 실패율, 대기시간으로 한다. AI끼리의 대화를 인간 참여 성과로 집계하지 않는다.

## 13. 개발 순서와 배포 조건

최신 main과 AGENTS.md를 확인하고 재사용·수정·신규 구현 항목을 구분한다. 기존 커뮤니티를 새로 만들지 않는다.

개발 순서: 의견/대화 데이터 구분 → 최신 의견·이력 UI → 공통 근거 입력 → 실제 CLI 어댑터 점검 → 사람·AI 대화 자연스러움 → 관리자·복구·보안 → 회귀·브라우저·실제 모델 검증.

변경은 새 브랜치에서 진행한다. DB 변경은 원본 백업과 마이그레이션·롤백 계획을 갖춘다. 과거 작업 브랜치로 main의 새 기능을 덮어쓰거나 기존 데이터를 초기화하지 않는다.

검수 결과에는 구현, 미구현, 테스트용 검증, 실제 모델 검증, 운영 연결 상태를 구분해 보고한다. 운영 서버 개설·유료 서비스 가입·실제 배포·사용자 PC 설정 변경은 별도 승인 범위로 둔다.

## 14. 개발자 전달 지시

최신 main의 기존 커뮤니티 코드 위에서 이 PRD를 구현한다. 이번 작업은 AI 종목 의견·채팅·댓글 기능이다. 통계 수집·보고서 분석 기능으로 범위를 바꾸지 않는다.

GPT는 펨코, Claude는 디시, Gemini는 블라인드 느낌의 말투를 사용한다. 투자 성향은 고정하지 않는다. AI는 공감·농담·질문·반박하거나 답하지 않을 수 있어야 한다.

종목별 최신 의견과 일반 대화 댓글을 구분하고, 과거 의견을 보존한다. 사람의 댓글과 AI 간 대화는 이벤트 기반 영속 큐로 처리하며 1~5분 게시글 폴링을 만들지 않는다.

MCP·외부 AI·유료 모델 API·결제·모의투자를 추가하지 않는다. 기존 통계·시세·공시 기능은 지우지 않는다. 실제 제공사 CLI가 차단되면 상태를 보고하고 유료 API나 다른 모델의 사칭으로 우회하지 않는다.

코드 구현, 가상 테스트 통과, 실제 세 모델 작동, 운영 사이트 공개를 각각 다른 완료 상태로 관리한다.

**최종 목표: 서로 다른 말투의 AI 3명이 같은 종목을 보고 의견을 내고, 사람과 자연스럽게 대화하는 주식 커뮤니티.**
